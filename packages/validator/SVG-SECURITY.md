# SVG Publication Policy

`svg-security.mjs` is the shared, non-mutating security boundary for API uploads,
admin generation, legacy validation, runtime catalog publication, V2 publication,
flag import and plugin resource publication. It uses direct runtime imports of
SAX and CSS Tree, with an accompanying TypeScript declaration.

- Strict XML parsing rejects malformed documents, duplicate attributes, multiple
  roots, processing instructions other than an initial UTF-8 XML declaration,
  DOCTYPEs and entity declarations.
- Element and attribute names are case-sensitive allowlists. All prefixed
  elements are rejected, including SVG-namespace scripts. Namespace rebinding,
  foreign namespaces and unknown prefixed attributes fail closed. The only
  inert editor declaration retained for compatibility is the exact existing
  Corel `xmlns:xodm` URI; it never permits prefixed elements or attributes.
- References must be literal local fragments. The sole data exception is an
  `image` element containing canonical base64 PNG bytes with a PNG signature,
  bounded dimensions, structurally bounded chunks and a terminal IEND. SVG,
  HTML, JPEG, external and relative data/resource references are rejected.
- CSS is parsed, not filtered by substring. Only allowlisted presentation
  properties, simple selectors, literal fragment URLs and color functions are
  accepted. At-rules, parser recovery/Raw nodes, escapes, custom properties,
  arbitrary functions and important declarations are rejected. The existing
  `var(--logo-color,#RRGGBB)` fallback is supported; this policy cannot define
  that variable or import an external definition.
- Validation returns the original bytes. Existing publisher normalization is
  unchanged for new SVGs. No asset or catalog is rewritten by the validator.

- `packages/logos/sourcing/variation-candidates/noor-takaful/01-alternate.svg`: DOCTYPE.
- `packages/logos/sourcing/web-candidates/youverify/02.svg`: JPEG data reference.

The first original is an approved source whose already-published canonical SVG
is declaration-free. It is not reparsed, rendered or republished as raw source
on a cache hit; its checksum-pinned public derivative is independently validated.
Unchanged private source provenance bytes are retained. A changed source or
render option invalidates this reuse and must pass the current policy.

## Render Preservation

`packages/brands/published-render-baseline.mjs` freezes the reviewed pre-upgrade
render input and format-record fingerprints. It was captured only after checking
all 5,459 protected asset/catalog hashes against the pre-security snapshot.
It is never regenerated by a build. `render-cache.mjs` allows reuse only when:

- Callers have verified the actual original source checksum.
- The source checksum, format, effective trim/enlargement/normalization options
  and versioned render recipe match the frozen input fingerprint.
- The complete format records match the frozen output fingerprint.
- All actual published output bytes match their catalog checksums; cached SVGs
  still pass the shared security validator.
- Any normalized source also matches the checksum in its content-addressed path.

Missing/corrupt cached bytes fail closed, never silently regenerate over trusted
outputs. New or changed inputs use the current renderer. Rendering code/settings
changes must version the recipe instead of updating the frozen baseline.

The cache is used by primary, historical and correction publishers and by the
corresponding admin generation paths. Native decoder upgrades therefore do not
automatically change previously reviewed public asset bytes or provenance.
